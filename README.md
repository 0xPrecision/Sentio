> **Sentio** — backend-проект для SaaS-платформы онлайн-записи в сфере услуг.  
> Репозиторий показывает основу многоклиентской архитектуры, HTTP API на FastAPI, сервисный и репозиторный слои, работу с PostgreSQL и бизнес-логику бронирований, расписаний и временных слотов.

## Обзор

**Sentio** разрабатывается как SaaS-платформа для онлайн-записи для салонов, студий, барбершопов и других сервисных бизнесов.

Текущая версия репозитория сосредоточена на серверной части системы: предметной модели, миграциях, API, сервисах, репозиториях и бизнес-правилах, связанных с бронированием. Telegram-бот рассматривается как один из клиентских интерфейсов, но в этой версии проекта он пока представлен только каркасом.

С практической точки зрения проект интересен тем, что показывает не просто набор CRUD-операций, а более зрелый подход к backend-разработке: с многоклиентской моделью, ролями доступа, сотрудниками, услугами, расписаниями, временными слотами и проверками бизнес-логики.

## Что уже реализовано

- многоклиентская предметная модель с ключевыми сущностями: `Tenant`, `Location`, `User`, `TenantUser`, `StaffMember`, `Service`, `StaffService`, `Customer`, `TenantCustomer`, `WorkSchedule`, `TimeSlot`, `Booking`
- ролевой доступ через Bearer JWT и определение tenant-контекста через заголовок `X-Tenant-Slug`
- FastAPI-модули для работы с бронированиями, услугами, сотрудниками, расписаниями и временными слотами
- сервисный слой с бизнес-логикой:
  - создание бронирования с блокировкой временного слота
  - проверка связи между сотрудником и услугой
  - отмена записи с различными сценариями статусов
  - перенос бронирования
  - валидация расписаний и временных слотов
- конфигурация Alembic и миграции базы данных
- локальная инфраструктура для PostgreSQL через Docker Compose, включая отдельную конфигурацию для тестов
- базовые тесты для отдельных утилит и части бизнес-логики

## Что находится в разработке

- подключение остальных API-модулей в итоговую сборку приложения

## Архитектура

Проект построен по многослойной архитектуре с разделением ответственности между основными частями приложения:

- **API-слой** — маршруты FastAPI, зависимости и обработка исключений
- **Слой схем** — Pydantic-модели входных и выходных данных
- **Сервисный слой** — бизнес-логика и прикладные сценарии
- **Слой репозиториев** — работа с данными через SQLAlchemy
- **Слой моделей** — ORM-сущности и связи между ними
- **Базовый слой** — конфигурация, база данных, перечисления, исключения и логирование

Ключевая особенность проекта — **многоклиентская архитектура**. Доступ к данным и операциям привязан к `tenant_id`, ролям пользователей внутри tenant-контекста и заголовку `X-Tenant-Slug`.

## Установка

Управление зависимостями выполняется через Poetry.

```bash
poetry install
```

Локальную PostgreSQL-базу можно поднять через Docker Compose:

```bash
docker compose up -d
```

Для тестовой базы предусмотрен отдельный compose-файл:

```bash
docker compose -f docker-compose.test.yml up -d
```

## Настройка

В репозитории пока нет готового `.env.example`, поэтому ниже приведён пример переменных окружения на основе текущей конфигурации проекта:

```env

JWT_ALG=HS256
APP_ENV=dev
LOG_LEVEL=INFO

POSTGRES_USER=sentio
POSTGRES_PASSWORD=sentio
POSTGRES_HOST=postgres
POSTGRES_PORT=5432

REDIS_URL=redis://redis:6379/0
SQLALCHEMY_ECHO=false
```

## Запуск проекта

### Применение миграций

```bash
poetry run alembic upgrade head
```

### Запуск API

Точка входа приложения находится в `sentio.api.main:app`.

```bash
poetry run uvicorn sentio.api.main:app --reload
```

```bash

poetry run black --check .
poetry run mypy .
```

## Текущий сценарий использования

На текущем этапе основной пользовательский поток в серверной части выглядит так:

1. создаётся сотрудник
2. создаётся услуга
3. услуга привязывается к сотруднику
4. создаётся рабочее расписание на дату
5. внутри расписания создаются временные слоты
6. на свободный слот оформляется бронирование
7. при необходимости бронирование можно отменить или перенести

### Пример запроса на создание бронирования

```bash
curl -X POST "http://localhost:8000/api/bookings/" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-Slug: demo-tenant" \
  -H "Content-Type: application/json" \
  -d '{
    "tenant_customer_id": 1,
    "staff_member_id": 10,
    "service_id": 5,
    "time_slot_id": 42
  }'
```

### Пример отмены бронирования

```bash
curl -X PATCH "http://localhost:8000/api/bookings/42/cancel" \
  -H "Authorization: Bearer <token>" \
  -H "X-Tenant-Slug: demo-tenant"
```

> На текущем этапе в основном маршрутизаторе приложения подключён только модуль `bookings`.  
> Остальные модули уже присутствуют в кодовой базе, но пока не включены в итоговую сборку приложения.

## База данных

Проект использует **PostgreSQL** в качестве основной базы данных и **SQLAlchemy** как ORM-слой для работы с моделями и связями между сущностями.

Структура данных построена вокруг предметной области сервиса онлайн-записи и включает сущности для работы с организациями, пользователями, сотрудниками, услугами, расписаниями, временными слотами и бронированиями.

Основные группы сущностей:

- tenants и locations
- platform users и tenant users
- staff members и services
- customers и tenant customers
- work schedules
- time slots
- bookings

## Инфраструктурные компоненты

### Уже используется

- **PostgreSQL** как основная база данных

- **структурированное логирование** через `python-json-logger`

## Развёртывание

На текущем этапе в репозитории подготовлена локальная инфраструктура для работы с PostgreSQL через Docker Compose, а также отдельная конфигурация для тестовой базы данных.

Полноценный production-контур развёртывания пока не реализован: в проекте отсутствует Dockerfile приложения, не настроен отдельный сервис для запуска backend в Compose и не представлены CI/CD-процессы.
